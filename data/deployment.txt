Процесс деплоя в продакшн

Все деплои в продакшн проходят через CI/CD пайплайн на GitHub Actions. Пуш в ветку main автоматически запускает сборку, прогон тестов и, если тесты прошли, деплой на staging-окружение. Деплой на продакшн из staging требует ручного approve от одного из тимлидов в интерфейсе GitHub Actions.

Откат (rollback) делается командой `deploy rollback --env production --to <version>`. Обычно откат занимает не больше 3 минут, потому что мы держим предыдущие 5 версий образов в реестре контейнеров.

Перед деплоем в пятницу после 16:00 по московскому времени нужно явное разрешение дежурного инженера — это правило ввели после инцидента в марте, когда пятничный деплой сломал биллинг и чинить пришлось в выходные.

База данных мигрируется отдельным шагом ДО деплоя нового кода, через `migrate up`. Миграции должны быть обратно совместимы минимум с предыдущей версией кода — иначе rollback кода без отката миграции всё сломает.
